# Capability: detect — scan the codebase's docs stack

The docs profile is the contract `produce` and `audit` work against — detect keeps it true.

## When

- First activation with no `{orchestration_dir}/docs-profile.yaml`
- The docs stack changed (new framework, moved docs root, new nav config file)
- `nav_config`'s mtime is newer than the profile's `detected_at` — someone edited the nav by hand and conventions may have shifted

## Run

```bash
uv run ./scripts/detect-docs.py --project-root "{project-root-resolved}" \
    --orchestration-dir "{orchestration_dir-resolved}"
```

## What it detects

| Framework | Tell | Nav contract |
|---|---|---|
| `vitepress` | `*/.vitepress/config.*` | `themeConfig.sidebar`/`nav` in the config file |
| `docusaurus` | `docusaurus.config.*` + `@docusaurus/*` dep | `sidebars.*` if present, else autogenerated |
| `mkdocs` | `mkdocs.yml` | `nav:` entries in the same file |
| `astro-starlight` | `astro.config.*` + `@astrojs/starlight` dep | `sidebar` in astro config |
| `nuxt-content` | `@nuxt/content` dep + `content/` dir | filesystem — page presence is visibility |
| `gitbook` | `.gitbook.yaml` + `SUMMARY.md` | links in SUMMARY.md |
| `plain` | `docs/` with markdown, no framework | none |
| `none` | no docs found | none |

`auto_zones` records directories the nav generates itself (e.g. a VitePress config that `readdirSync`s `orchestration/devlog`) — pages placed there need no manual registration.

## Output

Profile JSON verbatim; the file lands at `{orchestration_dir}/docs-profile.yaml`. `framework: none` is a real finding, not a failure — report it and let intake decide whether to scaffold a docs stack or keep markdown.
